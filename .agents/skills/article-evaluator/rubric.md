# 五维评分锚点

每维 0–10 整数分。评分时先定档位再微调。

---

## 1. 见识增益（权重 30%）

**核心问题：相对你的 wiki 已有知识，读完后认知是否有可描述的增量？**

| 分数 | 锚点 |
|------|------|
| 0–2 | wiki 已充分覆盖，或全是已知信息/口号 |
| 3–4 | 1 个浅层新事实，不改变既有认知 |
| 5–6 | 有增量但 wiki 已有类似框架，本文只是换表述 |
| 7–8 | wiki 未覆盖的新视角/框架，或显著深化已有认知 |
| 9–10 | 大幅拓展认知边界，且 wiki 无同题积累 |

**Wiki 对照规则**：评估前搜 wiki；若 ≥50% 核心观点已在 wiki 出现 → 本维 ≤ 5。

**加分信号**：挑战主流观点且有论证；把复杂问题讲清楚；提供「之前没想到的角度」
**减分信号**：「AI 将改变世界」类空话；罗列趋势但无洞察

---

## 2. 知识密度（权重 25%）

**核心问题：有效信息 / 总篇幅 的比例有多高？**

| 分数 | 锚点 |
|------|------|
| 0–2 | >70% 是废话、套话、重复、排版填充 |
| 3–4 | 有实质内容但被大量水分稀释，需读者自己过滤 |
| 5–6 | 中等密度，约一半内容有价值 |
| 7–8 | 大部分段落有信息增量，结构紧凑 |
| 9–10 | 几乎每段都有新信息，无冗余 |

**减分信号**：
- 同一观点用不同措辞重复 3 次以上
- 大量「背景介绍」占一半篇幅（面向完全小白且用户非目标受众）
- 10 张 PPT 图替代 10 段文字但无额外信息

---

## 3. 原创深度（权重 20%）

**核心问题：作者贡献了什么？是一手思考还是信息搬运？**

| 分数 | 锚点 |
|------|------|
| 0–2 | 纯搬运/翻译/洗稿；或大厂通稿 |
| 3–4 | 二手综述，无作者独立判断 |
| 5–6 | 有少量个人解读，但主要依赖他人观点 |
| 7–8 | 明确的作者立场 + 独立分析，有论据 |
| 9–10 | 一手实践/实验/调研；或原创理论框架/方法论 |

**大厂文特别规则**：
- 只展示成果（QPS、规模、团队人数）无方法论 → 原创深度 ≤ 3
- 分享架构决策 + trade-off 分析 + 失败案例 → 原创深度 ≥ 6

---

## 4. 可验证性（权重 15%）

**核心问题：文章的 claims 能否被检验？**

| 分数 | 锚点 |
|------|------|
| 0–2 | 全是断言，无数据、无来源、无代码 |
| 3–4 | 有模糊数据（「提升显著」）但不可复现 |
| 5–6 | 有具体数字或案例，但缺复现路径 |
| 7–8 | 有代码片段/架构图/实验设计，可部分复现 |
| 9–10 | 开源代码/完整 benchmark/详细实验 protocol |

**注意**：观点类文章（行业分析）此维权重自然降低，但 claims 仍应有来源。

---

## 5. 实践迁移（权重 10%）

**核心问题：读完后能否在工作中用上？**

| 分数 | 锚点 |
|------|------|
| 0–2 | 纯概念/纯宣传，无任何可迁移内容 |
| 3–4 | 知道「有什么」但不知道「怎么做」 |
| 5–6 | 有 general advice，缺具体步骤 |
| 7–8 | 有可操作的 checklist / 流程 / 避坑指南 |
| 9–10 | 可直接照着做：代码、配置、决策树、模板 |

---

## 加权计算示例

```
总分 = 见识增益×0.30×10 + 知识密度×0.25×10 + 原创深度×0.20×10
     + 可验证性×0.15×10 + 实践迁移×0.10×10

例：7/8/5/6/4
  = 21 + 20 + 10 + 9 + 4 = 64 → 🟡 值得阅读
```

## 红旗扣分参考

| 红旗 | 建议扣分 |
|------|----------|
| 大厂汇报型 | −3 ~ −5 |
| 追热点型 | −3 ~ −5 |
| 翻译搬运型 | −5 ~ −8 |
| 软文型 | −5 ~ −10 |
| PPT 型 | −3 ~ −5 |

扣分后总分不低于 0。若命中 ≥2 条红旗，阅读建议自动降一档（如 65 分 🟡 → 按 🟠 输出策略）。

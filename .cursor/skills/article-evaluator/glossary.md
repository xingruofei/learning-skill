# 追问：梳理名词/知识点

**触发**：梳理名词、陌生知识点、行话什么意思、读之前先搞懂概念

**目的**：读文章前/读不懂时，快速建立大致概念，**不是**写百科词条。

## 执行步骤

1. 从文章提取 **8–12 个**最影响理解的术语（缩写、框架名、方法论、领域词；跳过常识如「测试」「AI」除非文中有特殊用法）
2. 对每个术语 `search.py "<词>"` 或 grep `wiki/`；读匹配文的 summary/核心观点
3. 分类：
   - **🆕 对你可能是新的**：wiki 无覆盖，或 wiki 有提及但未解释清楚
   - **✓ 你已接触过**：wiki 已有清晰解释 → 指向路径，不重复展开
4. 对 🆕 项：**口语化** 1–2 句话，像跟朋友解释，不用教科书腔
5. 每项补 **「文中干嘛用」** 一列，挂钩文章上下文

## 输出模板

```markdown
## 名词/知识点速查

> 先搞懂行话再读文。🆕=wiki 里基本没有；✓=你知识库里已有。

### 🆕 对你可能是新的

| 名词 | 一句话搞懂 | 文中干嘛用 |
|------|-----------|-----------|
| CDP | Chrome 浏览器自带的「遥控接口」，能直接在页面里跑 JS，不用点 DOM | 绕过 EasyUI 黑盒，直接读 combobox 的值 |
| SDD | 先写规格（Spec）再写代码，变更都绑 Spec 编号 | 从 Spec 自动提取业务规则，生成 E2E 用例 |

### ✓ wiki 里已有 / 你已接触的

| 名词 | 你已知的大致意思 | 参考 |
|------|-----------------|------|
| Agent | 能调工具、多步干活的 AI 程序 | [Harness 文](wiki/articles/...) |
| Skill | 教 Agent 怎么干某类活的说明书 | 同上 |

### 读文提示
[1 句话：建议先搞懂哪 2–3 个词再读全文 / 哪一节名词最密集]
```

## 写作要求

- **口语化**：「就像……」「说白了……」「你可以把它想成……」
- **够读文即可**：不展开历史、不堆外链、不写超过 3 行的解释
- **wiki 优先**：✓ 类直接引用路径，避免重复 wiki 已有内容
- **诚实**：wiki 也没有的，标注「🆕 本文首次出现」；不确定则说「文中未展开」
- **优先阻塞项**：先列不懂就读不下去的词，次要术语可省略
